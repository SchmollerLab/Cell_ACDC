# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Python environment

**Always use this Python executable** for running code, tests, and scripts:

```
%USERPROFILE%\miniforge3\envs\acdc\python.exe
```

That is the `acdc` conda environment of the miniforge installation in the user's home folder (Python 3.13, PyQt6, pytest installed; no flake8/pyflakes, see Testing). Its editable install points to a different checkout (`~/repos/Cell_ACDC`), so run Python/pytest from this repo's root (`python -m ...` puts the cwd first on `sys.path`); scripts run from elsewhere (e.g. the scratchpad) need `PYTHONPATH=<this repo>` or they import the other clone. Write it as `~/miniforge3/envs/acdc/python.exe` in Bash and `$env:USERPROFILE\miniforge3\envs\acdc\python.exe` in PowerShell. Do not use a bare `python`/`pytest` from PATH. Examples (Bash):

```bash
~/miniforge3/envs/acdc/python.exe -m pytest tests/test_phase_translator.py -q
~/miniforge3/envs/acdc/python.exe -m pytest tests -k "measurement_viewer"
~/miniforge3/envs/acdc/python.exe -m cellacdc            # launch main GUI
~/miniforge3/envs/acdc/python.exe -m cellacdc.measurements_viewer [folder]
```

## Project overview

Cell-ACDC (Cell segmentation, tracking and event annotation) is a PyQt (via `qtpy`) + `pyqtgraph` desktop application for live-cell imaging analysis, from the Schmoller lab (Helmholtz Munich). Package: `cellacdc/`. Install for development with `pip install -e .` plus `requirements_gui_pyqt6.txt` (or the `gui` extra). Version comes from `setuptools_scm` (`cellacdc/_version.py`, generated).

Entry points (`pyproject.toml`): `cellacdc` / `acdc` / `Cell-ACDC` → `cellacdc.__main__:run` (GUI, or headless CLI when `--params <ini>` is given, see `cli.py` / `_run.py`); `acdc-setup-models` → `cellacdc.service.setup_models:main`.

## Architecture

The codebase is large; many core files are huge single modules (`gui.py` ~31k lines, `apps.py` ~25k, `widgets.py` ~15k, `workers.py` ~7.5k, `myutils.py` ~6.5k). Search with Grep rather than reading whole files.

- **Launcher** — `_main.py` (`mainWin`): the main launcher window that opens the modules (data prep, segmentation, GUI, utilities).
- **Main GUI** — `gui.py` (`guiWin`): the annotation/correction GUI. It is composed of many mixin classes from `gui_navigation.py`, `gui_annotations.py`, `gui_custom_annotations.py`, `gui_viewer_tools.py`, `gui_overlay.py`, `gui_combine.py`, `whitelist.py`. Mixins are shared with other windows, so changes there affect multiple windows. When merging `main`, its edits to methods that this branch moved out of `gui.py` show up as delete/modify conflicts in `gui.py`: port them into the mixin version (find it by method name) instead of re-adding the method to `gui.py`. Host-specific behaviour of shared code goes through hooks with main-GUI defaults, e.g. `ShortcutsGuiElements.showDeleteObjectShortcut`, `CustomAnnotationsGuiElements.canDeleteSavedCustomAnnot()` / `customAnnotColumnRemovalNote()`, the optional `bottomLayoutFont` read by `gui_overlay`, and `limitToLoadedColumns` of the combine dialogs (`True` only in the viewer).
- **Measurements viewer** — `measurements_viewer.py` (`MeasurementsViewerWin`, active development on branch `signal_gui`): standalone window that plots per-cell time courses of `acdc_output` columns, measurement-vs-measurement comparisons, combined measurements, measurement processing, time point identifiers, custom annotations and phases. It reuses the GUI mixins above and loads its own data; configurations are saved as JSON in the settings folder. The module docstring is an extensive spec—read it before changing behavior. Users open it from the launcher (Utilities > Measurements > Measurements viewer..., `_main.mainWin.launchMeasurementsViewer`). User docs: `cellacdc/docs/source/measurements-viewer.rst`, linked from the viewer's Help menu, info buttons and the phase translator dialog via `urls.measurements_viewer_docs_url` (+ `#<section-title-anchor>`): renaming a section breaks the links (`test_docs_page_has_the_linked_sections`).
  - Non-UI code lives in `measurements_viewer_utils.py`: module functions (loading, `last_analyzed_frame`/`mask_frames`, `evaluate_masked_cell_equation`, `signal_color`, `get_logger`, ...) and the `MeasurementsViewerUtils` mixin with the window's data/logic methods (tables, configuration validation, predictors bookkeeping, phases), inherited right after `QMainWindow` (so Qt attribute names would shadow its methods). Put new widget-free methods there (they must not call UI methods of the window); `measurements_viewer` re-imports the moved module names, but patch functions called inside the utils module there (tests patch `measurements_viewer_utils.load_position`). Never import `measurements_viewer` from it (circular).
  - Overlay channel image items are added to `ax1` when data loads (after the annotation items), so annotation layers need explicit z-values to stay visible (`gui_createAnnotationsWidgets`: 0.5–0.6; custom annotation symbols 0.6 via the viewer's `addCustomAnnnotScatterPlot` override; ruler and mirrored cursor 0.9 in `gui_createGraphicsPlots`; on-demand items (object tracks, scale bar, timestamp) 0.9 via `raiseOnDemandAx1Items`, so add new on-demand ax1 items there; text IDs are at 1).
  - `getAcdcDf` rebinds `posData.acdc_df` on every position load, so never detect stale tables by DataFrame identity: measurement processing merges only its output columns at completion and checks `posData.acdcDfReloadCount` (bumped in `reloadAcdcDfFile`). Tables are normalized on load/reload by `normalize_loaded_acdc_df` (`load._load_acdc_df_file` fills NaN with 0 in non-cca columns when cca columns exist, so phases go through `phase_translator.normalize_loaded_outputs`); `saveAcdcDfs` checks `posData.acdcDfFileStamp` for files changed on disk. Read stored flag columns (`timepoint_*`, `measurements_viewer_visited`, custom annotations, `phase_<name>`) only with `timepoint_predictors.parse_flags` (`strict=True` to also recognise whether a column is a flag column, as for phase markers), never `astype(bool)` or `pd.to_numeric(...) != 0`: the main GUI's `store_data` reindexes with `fill_value=0`, so they come back as `'True'`/`'False'`/0 strings. Each measurement-step output column comes from exactly one recorded step (`recordMeasurementStep` replaces an exact-output match, ordered by `measurementStepReplacementOrder`; `validateMeasurementSteps` rejects duplicates and steps reading outputs of a later step). Session auto-prediction tracking (`timepointAutoPredictions` / `customAnnotAutoPredictions`) is reset by `resetAutoPredictionTracking` whenever data loads and rebuilt from the visited column via `seedVisited*`; enabling auto apply or editing a predictor must not re-predict visited cells. Removed QActions stay children until `deleteLater` runs and `reservedShortcuts` (findChildren) still sees them: clear their shortcut first.
  - Shortcuts: a time point/annotation shortcut K gets the auto (re-evaluate) shortcut Shift+K (`auto_shortcut_text`), so K is reserved when Shift+K is taken (`reservedShortcuts`); premade templates are checked by `test_premade_shortcuts_do_not_collide`. Give new viewer actions a non-Shift modifier shortcut (e.g. `Alt+P` of `applyPhasesCellAction`) and register them in `widgetsWithShortcut` (editable), so they block neither single-letter defaults (`timepoint_predictors.DEFAULT_SHORTCUTS` Q–P, `custom_annotation_predictors.DEFAULT_SHORTCUTS`) nor their Shift+K auto shortcuts. Renaming a predictor output column is refused while other predictors/formatting reference it (`columnDependents`), because equations are not rewritten.
  - Time-course plotting (`plotMeasurements`): `connectSignalPoints` re-calls `scatter.setData`, so per-point options (brushes) must be passed again there. With a pyqtgraph `connect` array, non-finite points are back-filled and lines bridge NaN gaps unless the neighbouring segments are masked out (see conditional formatting).
  - Plot colors: get a column's color only via `getSignalColor(col)` (custom color from `measurementsColors`, saved as the configuration's `measurements_colors` `{col: '#rrggbb'}`, so templates can preset them; else the stable per-column default from `defaultSignalColorIndex` over the Okabe-Ito `SIGNAL_COLORS`); red belongs to the line cursors (current frame line), so default colors avoid it (vermillion only as the last palette color; also `phase_translator.DEFAULT_PHASE_COLORS` and `ConditionalFormattingDialog.DEFAULT_COLORS`; fallbacks skip red hues, checked with `is_reddish` in `tests/test_measurement_viewer_review_feedback.py`). `signal_color(light_background=...)` swaps the Okabe-Ito yellow for black on the inverted background (`recolorSignalsForBackground`). `qutils.QControlBlink` stops a still-running blink of the same widget (`_active`), so repeated blinks restore the original style.
  - Partially analyzed videos: `posData.lastAnalyzedFrame` (`last_analyzed_frame`: last cca-annotated frame, else max `frame_i`; set in `load_position` and `reloadAcdcDfFile`). With `maskUnanalyzedFrames` (config `mask_unanalyzed_frames`) every calculation must go through `analysisLastFrame` / `analysisDf` / `analysisSizeT` (never `posData.SizeT`, which stays the display/navigation size): cut only the table passed to the computation and write results into the full table (rows must never be dropped); library entry points take `phase_translator.evaluate(last_frame=)` / `apply_recipe(max_frame_i=)`; worker code gets the frame as a plain int (`replayMeasurementSteps(last_frame=)`, `setupJob(max_frame_i=)`). The load prompt (`resolveMaskUnanalyzedFrames`) runs on the GUI thread between the loading worker and the step replay. Masked NaN step outputs come back as 0 from tables with cca columns, so the frame each position's steps were calculated up to is recorded (`measurementStepsLastFrames` / config `measurement_steps_last_frames`, `recordStepsLastFrame`) and outputs are re-blanked after `min_frame(recorded, current)` in the acdc_df and its `savedAcdcDf` snapshot (`blankStepOutputs`); masked bool outputs go through `float_if_bool` (object columns drop out of the plottable list). Shaded `LinearRegionItem`s must not get a tool tip: it hides the points' hover info (ViewBox tool tip).
  - Phase names that CSV reading turns into numbers/booleans/NA (e.g. `'1'`, `'NA'`) are recovered from the boolean `phase_<name>` columns (`phase_translator._phase_strings`), so phase names need no extra validation.
  - Phase display: `phaseBandPlot` is a separate `PlotWidget` x-linked below `measurementsPlot` (left axis width synced via `syncPhaseBandAxisWidth`); redrawn by `updatePhaseBand` from `plotMeasurements`. Colors: `phase_translator.phase_colors` + `self.phaseColors` overrides.
  - Persist display-only per-user toggles (e.g. "Show phases") with `gui_core.GUICoreElements._get_setting_value` / `_set_setting_value` (settings CSV); options that change analysis behaviour (e.g. `auto_apply_phases`) belong in the viewer configuration (`configuration()` / `validateConfiguration` / `loadConfiguration`).
  - Logging: `self.logger` = `measurements_viewer_utils.get_logger()` (stdout handler attached once, writes to the *current* `sys.stdout`, `propagate=False`), so test log output with `capsys`, not `caplog`. Log user actions in viewer-owned handlers with `self.logger.info` (short, with column names/IDs/paths), never per frame scroll step or hover.
  - Premade configurations: templates in `cellacdc/measurements_viewer_premade_configurations/*.json` with `channel_placeholders`, optional typed `input_placeholders` (values asked at setup, with info text), optional setup-only `channel_hints` (name parts that preselect each placeholder's channel, e.g. gfp/mcherry for FUCCI) and `background_values` sections (links inputs to the background utility's summary table; setup dialog buttons Calculate/Load; Calculate asks only the Positions of the selected experiment via `utils.computeBackgroundValues.select_positions`; keys listed in `PREMADE_TEMPLATE_KEYS` are dropped from the written configuration) and `{NAME}` tokens; on load they are resolved and copied into the settings folder (`instantiatePremadeConfiguration`). Resolve templates in code/tests with `MeasurementsViewerWin.resolvePremadeTemplate` (fills input defaults), not by popping `channel_placeholders` by hand. In template equations/predictors/conditions wrap token-built column names in backticks (`` `{RED}_mean` ``): substitution unquotes plain identifiers, and channels that pandas cannot parse even quoted (digit first or right after a dash, e.g. `561`, `GFP-488`) are rejected (`isEquationName`; the mapping dialog's `validate` callback). Keep such checks explicit (regex), never based on `tokenize`/pandas parsing alone: Python 3.10/3.11 tokenize `561_mean` without error, 3.12+ rejects it. Python 3.11/3.12 interpreters without project deps are under `~/.pyenv/pyenv-win/versions/` for syntax/tokenizer checks. `channel` may be empty in any configuration (e.g. FUCCI: both reporters are overlays): the display channel is asked when loading (`selectDisplayChannel` / `resolveInputChannel`), so code after input selection can rely on a non-empty `channel`.
  - `plotMeasurements` resets the time-course x range only when `_timecourseXRangeKey` changes (cleared on `loadPosition` and in comparison mode), and fits y (`fitTimecourseYRange`) only when `_timecourseYRangeKey` (plotted columns + normalization) changes or x was reset; the fit then re-enables pyqtgraph's y autorange with `setAutoVisible(y=True)`, so y follows the data in the visible x range (cell changes) until the user zooms/pans by hand. Tests call `viewBox.updateAutoRange()` before reading the range.
  - The "Cell-ACDC objects" dock follows `selectedID` (`syncPropsDockToSelectedID`, called in `updateImages`); every code write to its `idSB` (emits `valueChanged` on any `setText`) must run under `_isUpdatingPropsDock` (the viewer's `updatePropsWidget` override sets it), else `propsWidgetIDvalueChanged` treats it as a user edit and selects that cell.
  - Loading (`loadImagesPaths` / `loadConfiguration`) reads positions (`load_display_positions`, which also precomputes the first position's regionprops for `initPosAnnotData`) and replays measurement steps in a worker via `runInThread` (local `QEventLoop`, window disabled, exceptions re-raised in the caller). Tasks must not touch widgets or show dialogs (`loadTrackedLostCentroids` can, so it stays on the GUI thread). `myMessageBox`/`QBaseDialog` are non-modal, so `_isLoadingData` (`loadingInProgress`) refuses re-entrant loads and closing during a load, `_isClosingPrompt` refuses loads while the closing prompt is open, and loads/measurement processing refuse each other (`refuseLoadingWhileProcessing` / `refuseProcessingWhileLoading`, checked again after the non-blocking dialogs). Overlay channels of a configuration are read in the worker too (`preload_overlay_channels`, taken by the viewer's `load_fluo_data` override). `runInThread` also disables the other top-level windows: a dialog opened there would nest its event loop in the wait. `setData` starts the Cell ID blink with `QTimer.singleShot(0, ...)` (after the rest of the load), so tests call `processEvents()` first. Qt's `close()` is re-entrancy-guarded (a nested `close()` returns True without a `closeEvent`).
  - Predictor fast paths (`OtherCellMeasurements` block emission and `_equality_candidates` value index for lineage sources, `TimepointPredictor._evaluate_all_cells` for row-wise equations via `CellEquation.is_row_wise`) must stay exactly equivalent to the per-target/per-cell paths; `tests/test_predictor_fast_paths.py` disables them to compare.
  - `timepoint_predictors.py`: time point identifiers and predictors (equations over acdc_df columns with per-cell functions like `MAX`, `DIFF`, `SHIFT`; filters; other-cell aggregates; frame windows; Python-file `predictor(df)`), dependency ordering of interdependent predictors. Classes: `TimepointIdentifier`, `TimepointPredictor`, `CellEquation`, `CellFilter`, `OtherCellMeasurements`, `CellTable`, `FrameRange`, `PredictorDependencies`.
  - `custom_annotation_predictors.py`: boolean per-cell annotations built on the same machinery, consolidated with All/None/Most.
  - `phase_translator.py`: translates ordered time point boundaries into `phase` / `phase_<name>` columns per rule. `annotation_overrides` (`evaluate` / `validate_rules` / `output_columns` / `phase_names`; the viewer passes a list from `phaseOverrideAnnotations()`, custom annotations with state `overridesPhases`, viewer only) take precedence over all rules (annotation name as phase on all analyzed rows, first in toolbar order wins) and are appended after the rule phases in `phase_names`, so rule colors do not shift. Guard phase actions with `hasPhaseTranslation()`, not `phaseTranslatorRules`.
  - Phase auto apply on annotation changes (`schedulePhaseAutoApply`) is scheduled only for cells whose annotation value changed (option toggled / renamed / removed: `schedulePhaseOverrideCells`), never while annotations are set in bulk (`setCustomAnnotations`, `reinitCustomAnnot` run under `bulkSettingCustomAnnotations`), or loading would re-evaluate the saved phases of every cell.
  - `measurement_processing/`: plugin steps (see below).
  - `_equations.py`: equation evaluation used by "Combine measurements".
- **Dialogs and widgets** — `apps.py` (dialogs/windows), `widgets.py` (custom widgets), `_base_widgets.py`. Dialogs used only by the measurements viewer (phase translator, time point identifier and predictor/filter equation editors, custom annotation predictor group box, measurement processing recipe, channel/input setup, conditional formatting) live in `apps_measurements_viewer.py`. Example: background intensity (Utilities > Measurements; core in `background_values.py`, docstring = spec). ## Plugin conventions (discovered by folder name)

- **Segmentation models** — `cellacdc/models/<Name>/acdcSegment.py` with a `Model` class exposing `__init__(...)` and `segment(image, ...)` returning a label array. Init/segment keyword arguments with defaults become GUI parameters. Folders starting with `_` are ignored. See `models/thresholding/acdcSegment.py` for a minimal example.
- **Trackers** — `cellacdc/trackers/<Name>/<Name>_tracker.py` with a `tracker` class and `track(segm_video, signals=None, ...)`.
- **Promptable models** — `cellacdc/promptable_models/<name>/`.
- **Measurement processing** — `cellacdc/measurement_processing/<Name>/acdcProcess.py` with module-level `name` and a `Model` class with flags `is_timelapse`, `is_bulk_processing`, `numeric_input` and a `@staticmethod` `run(...)` (`Model` is never instantiated; a non-static `run` is skipped at load). See `SmoothMeasurement`. Recipes in configurations reference the module `name` (e.g. `"Ramp detection"`), not the folder name. NumPy-style `run` docstring parameters become the per-option info buttons; JSON kwargs are passed without type conversion, but recipe INI files store every kwarg as a string: cast them with `MeasurementProcessingParamsWidget.castRecipeValue` (bools via `ConfigParser.BOOLEAN_STATES`), never `bool(str)`. Plugins that fail to import, lack a non-empty `name` or `Model.run`, or repeat a `name` are skipped with a `RuntimeWarning` (first wins); `_load_processors(folder, package)` can target a tmp package in tests. Existing: `SmoothMeasurement`, `MinMaxNormalization` (fixed constants), `RampDetection` (FUCCI ramps, used by `fucci_cell_cycle.json`).
- `measurement_processing.apply_recipe(df, cols, recipe, new_colnames)` appends one output column per input and rejects mismatched, duplicate or already existing output names; `workers.MeasurementProcessingWorkerGUI` is one-shot (`setupJob` + `runJob`, result via `sigDone`).

## Data layout

Experiments are organized as `<exp_folder>/Position_<n>/Images/` containing `<basename><channel>.tif`, segmentation `<basename>segm*.npz`, the annotations/measurements table `<basename>acdc_output*.csv` (one row per `frame_i` × `Cell_ID`), and metadata CSV/JSON files. `acdc_df` in code refers to the `acdc_output` table (indexed by `frame_i`, `Cell_ID`).

Every save also writes a snapshot to `Images/recovery/<basename>acdc_output.zip` (`load.store_copy_acdc_df`). The archive keeps about 21 `iso<timestamp>.csv` members and drops the oldest, so diffing consecutive members shows when bad values first appeared. Each save re-reads every member and casts it with `pd_bool_and_float_to_int_to_str`. A traceback printed during a save can therefore come from an old member rather than the table you just saved.

## Testing

- Tests live in `tests/` (pytest; config in `pyproject.toml`, which ignores `cellacdc/test_tracker.py` and DeprecationWarnings). Shared helpers in `tests/utils/`, sample data in `tests/test_data/`.
- Qt tests create a module-scoped `QApplication.instance() or QApplication([])` fixture and drive widgets with `QTest`; dialogs that would block are monkeypatched (see `tests/test_measurement_viewer_configuration.py`). No pytest-qt.
- UI tests must run offscreen and never block (user requirement): `tests/conftest.py` sets `QT_QPA_PLATFORM=offscreen` (override the env var to watch the UI) and a watchdog auto-answers any dialog still blocking after 0.3 s (OK/default button, `ok_cb`, accept), reported as `AutoAnsweredDialogWarning` (handles `myMessageBox`, plain `QMessageBox` and other dialogs; see `tests/test_conftest_dialog_watchdog.py`). Still monkeypatch dialogs whose answer matters. Tests that run a real worker `QThread` under `exec_` request the `_auto_answer_blocking_dialogs` fixture and call its `.stop()` (else the watchdog answers the progress window). The conftest also redirects user settings (`settings_folderpath` and the module-level settings/metadata/recent-paths/shortcuts/custom-annotation paths, QSettings) to `tmp_path` (autouse `_isolate_user_settings`) and destroys `deleteLater()`'d widgets after each test (`flushDeferredDeletes`; outside an event loop `processEvents()` never deletes them).
- Keep tests fast (user requirement): a test file should take seconds, not minutes. Use small synthetic tables (tens of cells/frames), keep parametrized grids and random parity/fuzz cases to a handful, avoid long `qWait`s, and check new tests with `pytest --durations=15`. Benchmarks and large fuzz runs belong in scratch scripts run with a timeout, not in the suite. Slowest files now (~1-2 min each): `test_equation_inputs.py`, `test_measurement_viewer_configuration.py`, `test_predictor_fast_paths.py`, `test_timepoint_identifiers.py`, `test_measurement_viewer.py`.
- Never assert inside a `QTimer.singleShot` slot in tests: an exception there aborts the whole pytest process. Record values in the slot and assert after the blocking call returns.
- The identity `Dummy` measurement processor is test-only (`tests/utils/measurement_processing.py`); tests get it through the `dummy_processor` fixture.
- Some tests need optional model environments/GPU/network (`test_all_model_environments.py`, `test_gpu_availability.py`, `tests/segm`, `tests/prompt_segm`); prefer running targeted test files.
- Local lint: flake8/pyflakes are not installed in the `acdc` env. Install them into a scratch folder without touching the env (`python -m pip install --target <dir> flake8 pyflakes`) and run `PYTHONPATH=<dir> python -m flake8 --select=E9,F63,F7,F82 <files>` (the CI check) / `python -m pyflakes <file>`; `python -m py_compile <file>` for a quick syntax check.
- Run Qt test files one at a time (`pytest tests/<file>`): since the conftest flushes deleted widgets, one pytest process over the whole suite also passes (as in CI), but a crash there may not print a summary.
- The measurements viewer's recipe dialog offers only measurement leaves of a hierarchical model (group headings are not selectable); tests select leaves by name and must enter a non-colliding output suffix before `ok_cb()`.
- Importing `cellacdc.measurements_viewer` in a bare `python -c` script prints a caught `regionprops.py` traceback (`app.mainWindow`) but works; smoke-test widgets through pytest instead.
- CI (`.github/workflows/`) runs `flake8 --select=E9,F63,F7,F82` (syntax errors / undefined names must not occur) and `pytest` on Python 3.10–3.13: PyQt5 and PyQt6 on Windows and macOS, PyQt5 only on Ubuntu.
- Platform pitfalls seen in CI: on macOS shortcut texts use macOS key names (`KeySequenceFromText.toString()`, `ShortcutLineEdit` display text, `ShortcutEditorDialog.new_hard_shortcuts` give `Command+O`; `ShortcutLineEdit.text()` gives `Ctrl+O`), so compare `QKeySequence`s or use `widgets.windowsShortcutToMac` in tests, and simulate with `monkeypatch.setattr(widgets, 'is_mac', True)`; macOS ignores `QMessageBox.setWindowTitle`; Qt5 `QAction.trigger()` emits `triggered` even for a disabled action, so handlers must not assume loaded data; Windows CI checks out on `D:` while tmp is on `C:` (`os.path.commonpath`/`relpath` raise `ValueError`); Python 3.10/3.11 `tokenize` recovers from errors (e.g. an apostrophe in a backtick name) that 3.12+ raise on. `QMutex.unlock()` on an unlocked mutex segfaults with Qt5 (Qt6 tolerates it, so the local PyQt6 env hides it): release "maybe locked" mutexes with `tryLock()` + `unlock()` (as `workers.worker_exception_handler` does).
- To test PyQt5 / Python 3.11 locally: make a venv from `~/.pyenv/pyenv-win/versions/3.11.9/python.exe` and `pip install pytest -e . -r requirements_gui_pyqt5.txt`. On Windows, showing a plain `QMessageBox` with Qt5 on the offscreen platform crashes the interpreter (also in CI, killing the whole pytest run): tests that show one get the `shows_qmessagebox` skip mark (`test_conftest_dialog_watchdog.py`); use `QT_QPA_PLATFORM=windows` to run them locally.

## Code style notes

- Use `qtpy` imports (not `PyQt6` directly) so PyQt5/PyQt6/PySide all work.
- GUI code uses Qt-style camelCase method names; newer non-GUI modules (predictors, phase translator) use snake_case functions and class-based APIs with thorough docstrings.
- Keep module docstrings in sync when changing behavior of the measurements viewer and predictor modules—they serve as the specification.
- Main branch for PRs: `main`.
